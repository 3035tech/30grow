29 dependências diretas revisadas: 23 de produção e seis de desenvolvimento.

23 têm uma versão mais recente na tag latest do npm. Após as correções de segurança desta entrega, a auditoria de produção reporta zero vulnerabilidades; a auditoria completa mantém três alertas moderados associados à mesma cadeia Tailwind/PostCSS.

Atualização posterior: lote compatível implementado com Node 22.23.4, Next/eslint-config-next 16.4.3, React/React DOM 19.3.1, pg 8.23.1, jose 6.2.13, Stripe 23.0.1 e SDKs AWS 3.1156.0.   • Zod: 4.4.3 → 4.6.6, correção da vulnerabilidade alta que bloqueava o Actions.
  • Nodemailer: 10.0.10 → 10.1.4, correção dos alertas do parser de endereços.
  • fast-uri: 3.1.8 → 3.1.9, atualização transitiva compatível.
  • Foram alterados apenas os manifests/lockfile para essas correções, mantendo o gate de auditoria ativo.

Ordem recomendada

  1. Publicar as correções de segurança já testadas. A execução anterior passou em release-contracts e parou apenas em analytics-contract na auditoria de runtime.
  2. Padronizar Node e executar um lote compatível. Next e eslint-config-next 16.4.3; React e React DOM 19.3.1; pg 8.23.1; jose 6.2.13; Stripe 23.0.1; SDK AWS 3.1156.0. Tratar o lote como candidato de atualização, com testes, sem assumir que a tag latest prova estabilidade neste aplicativo.
  3. Ferramentas e patches intermediários. Playwright 1.64.1 com seus navegadores; Autoprefixer 10.6.1; PostCSS 8.5.31, revisando o override do Next; @signpdf 3.4.0 coordenado; pdf-parse 1.1.4; Recharts 2.15.4. Zod 4.6.7 e Nodemailer 10.2.1 podem entrar neste ciclo após validação.
  4. Migrações separadas. Tailwind 4, Sentry 11, Recharts 3, pdf-parse 2, @signpdf 4, bcryptjs 3 e ESLint 10. Cada grupo exige critérios próprios e rollback por lockfile; não aplicar npm audit fix --force de forma indiscriminada.

Achados de qualidade e compatibilidade

  • Node divergente: analytics-contract usa Node 24; release-contracts e Docker usam Node 22; a máquina de validação usa 24.11.0. Padronizar a linha e testar com a versão real do container. A tag node:22-alpine é móvel; considerar versão/digest controlado.
  • Alertas de build: postcss-selector-parser, postcss-nested e tailwindcss são os três pacotes sinalizados na cadeia do parser. O npm indica Tailwind 4 como solução automática. A exposição no projeto não foi comprovada por teste de exploração; não classificar o problema como inofensivo apenas por estar em devDependencies.
  • Sentry: o build já avisa sobre withSentryConfig importado da raiz, disableLogger, automaticVercelMonitors e sentry.client.config.js. Revisar esses pontos antes da major 11.
  • PDF: lib/candidate-cv.js usa uma importação interna do pdf-parse v1. Isso merece migração explícita para API pública antes de adotar v2.
  • Autenticação: bcryptjs 3 precisa provar compatibilidade com os hashes existentes. Não exige, por decisão desta auditoria, redefinir senhas ou alterar usuários.
  • Lint: há ESLint instalado, mas falta um comando de lint padronizado em package.json. Definir esse gate antes de uma atualização major do linter.
  • PostCSS: há a versão direta 8.5.26 e um override do Next para 8.5.28. Rever ambos em conjunto ao atualizar Next e PostCSS.
